# 1. 群組對話經 Power Automate 和私人 repo 讀取

日期：2026-11-18

## 背景

昨日群組回顧和每週群組觀察（潛水、已讀不回、本週話最多）需要讀午餐好夥伴群組的對話。
這個 repo 和它的 Actions 紀錄是公開的，對話內容和每個人的發言次數不能出現在這裡。

## 決定

- Power Automate 的排程流程用擁有者自己的 Teams 連線讀群組訊息，
  經 GitHub 連接器的 repository dispatch 送進一個私人 repo。
- 私人 repo 的 workflow 請 Claude 寫回顧、更新每人每天的發言與 reaction 次數，
  分析完就刪掉那筆執行紀錄。長期只留寫好的回顧文字和次數，不留對話原文。
- 這個公開 repo 的早安卡用金鑰去讀寫好的文字，不把它印進紀錄。讀不到時卡片照發，少掉這兩段。

## 沒有採用的做法

- **開發機直接用 Microsoft Graph 讀聊天**：最簡單，對話也不必經過 GitHub，
  但公司租戶不允許使用者自行同意 Chat.Read，登入時顯示需要管理員核准（2026-11-18 實測）。
- **Power Automate 的通用 HTTP 動作**：設計畫面上找不到，無法直接呼叫外部服務。
- **在這個公開 repo 處理**：workflow 的輸入和紀錄任何人都看得到。
- **補抓過去 8 週訊息**：要在 Power Automate 多做一個翻頁流程；改成從上線日開始累積，
  滿 4 週才第一次公布榜單。

## 後果

- 讀取靠擁有者的 Teams 連線，連線過期或擁有者離開群組時，回顧和榜單會停，卡片本身不受影響。
- 沒有事先徵求群組成員同意；補救是排除名單，誰提出就不再統計也不寫進回顧。
- 對話原文會短暫經過 GitHub（私人 repo 的一次執行），並送到 Claude API。
